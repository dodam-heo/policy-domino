# POLICY DOMINO NEXT

**정책 도미노의 기본 산출물은 '새 게시글'이 아니라 기관별 업무·제도·서비스·시스템의 변경 필요사항입니다.**

배포 주소: https://dodam-heo.github.io/policy-domino/

## 2026-11-08 재구축 내용

기존 RSS/보도자료 수집 코드를 새 실행 경로에서 **완전히 제외**했습니다. 이전 `.github/workflows/policy-domino.yml`는 삭제됐고, `.github/workflows/auto-watch.yml`는 이제 `next/engine.py`만 실행합니다.

### 구성
1. **변화 감지:** 법제처 국가법령정보센터의 공포 법령 목록과 공포·시행 정보 조회. `법령ID + 공포일 + 공포번호`로 개정 사건을 식별합니다.
2. **변경 전후:** 동일 법령의 연혁 버전과 조문 본문을 비교해 변경·추가·삭제된 조문을 구조화합니다. 비교할 이전 조문이 없으면 임의로 생성하지 않습니다.
3. **조치 도출:** 변경 조문에서 소관부처·법정 업무주체와 자격, 신청, 금액산정, 제출서류, 심사, 처리기한, 고지·안내, 준수·감독 등의 업무유형을 확인해 기관별 검토사항으로 생성합니다.
4. **전체 목록:** 모든 조치를 한 번에 표시하고, 조치 확인 / 미조치 확인 / 반영 확인 필요 / 시행 예정 상태를 개별 항목 옆에 표시합니다.
5. **근거 추적:** 각 항목에 제·개정 법령, 변경 조문 전후, 공포일, 시행일, 기관 역할과 법제처 원문 링크가 연결됩니다.
6. **한계 관리:** 공적 근거가 없는 개별 기관·업무·시스템명이나 조치 완료 여부는 만들어 내지 않습니다. 수집 실패도 '변경 없음'으로 표시하지 않습니다.

## 데이터·테스트

- 백엔드: `next/engine.py` (파이썬 표준 라이브러리만 사용)
- 웹 UI 원본: `next/index.html`, 배포 파일 `site/index.html`
- 자동 테스트: `next/test_engine.py` → 동일 법령 신구조문 비교, 변경이 없으면 조치 미생성, 실제 법적 업무 주체·시행예정 판정
- 데이터: `site/data.json` → `policy-domino-next-v1` 스키마
- 이력: `data/next_state.json`
- 실행 확인: `data/next_run_status.json`
- 배포 확인: `data/next_deploy_status.json`

## 실제 자료 연결 조건

**`LAW_OC` 인증값이 필요합니다.** 법제처 공식 API의 필수 `OC`값이며, [공식 신청](https://open.law.go.kr/LSO/openApi/guideResult.do) 후 저장소 [Actions secrets](https://github.com/dodam-heo/policy-domino/settings/secrets/actions)에서 `LAW_OC` 이름으로 등록해야 합니다. 인증값을 코드에 하드코딩하거나 공개 저장소에 올리지 마세요.

인증이 없으면 공개 최근공포법령 페이지에서 공식 확정 메타데이터를 수집하도록 시도하되, **신구조문 접근이 안 되므로 상세 변경·영향 분석을 완료로 표시하지 않습니다.** 공식 페이지에 접속할 수 없는 네트워크 환경에서는 최신 변경 데이터가 공백이며 수집 실패가 표시됩니다. 이 경우 **운영용 공식 API 연결이 선행돼야 합니다**.

## 현 단계에서 남은 구현 범위

이번 버전은 **독립된 새 코드의 기본 엔진과 웹 서비스**이며, 전국 모든 관련 기관과 개별 사업을 전수 식별하는 완제품이라고 주장하지 않습니다. 중앙·지방·공공기관의 공식 서비스·조직·사업 등록정보를 상호 연결할 기관/업무 지식그래프, 법률 이외의 독립된 정책기준 변경 소스, 공식 대외 서비스에서의 조치상태 자동 검증과 경과조치 검증을 확장해야 합니다.

실제 조치 상태는 근거가 확인된 경우만 확정합니다. 내부문서나 내부시스템의 열람은 범위에 포함하지 않습니다.
